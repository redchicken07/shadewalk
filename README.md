# 🌳 그늘길 (ShadeWalk)

> **해를 피해, 그늘 따라 시원하게 걷기.**
> 건물 그림자를 시간대별로 직접 계산해서, 그늘로 걷는 경로와 산책 코스를 추천하는 웹앱입니다.

무더운 날 A에서 B까지 갈 때 — 최단 경로 대신 **그늘이 가장 많은 길**로,
지하도·실내 통로까지 포함해서 안내합니다. 산책하고 싶을 땐 지금(또는 미래) 시각의
그림자를 계산해 **그늘 비율이 높은 순환 코스**를 골라 줍니다.

API 키·백엔드·빌드 도구가 **전혀 필요 없는 100% 정적 웹앱**이라
`index.html`을 열기만 하면 동작하고, GitHub Pages에 그대로 올릴 수 있습니다.

지도 데이터는 **미리 구워서 `data/` 폴더에 넣어 둡니다.** 앱이 실행 중에는 외부 API를
한 번도 부르지 않아서 — 호출 제한도, 비용도, 이용약관 문제도 없고, 로딩도 즉시입니다.
검색까지 그 안에서 처리하므로 **비행기 모드에서도 동작합니다.**

---

## ✨ 주요 기능

| 기능 | 설명 |
|---|---|
| 🕶 **실시간 그림자 지도** | OSM 건물 외곽선 + 높이(층수) × 태양 위치(SunCalc)로 그림자 폴리곤을 직접 계산해 지도에 표시 |
| ⏰ **시간 슬라이더 + 재생** | 지금부터 +12시간까지 10분 단위로 그림자 변화 미리보기. ▶ 버튼으로 하루 그림자 흐름을 애니메이션 |
| 🧭 **경로 3종 비교** | ⚡최단 / 🌳그늘 / 🚇지하도 를 **동시에 계산해 나란히 비교**. 카드를 누르면 지도에 표시되고, 나머지는 회색 점선으로 겹쳐 보여 차이가 한눈에 |
| 🚇 **지하도 전용 경로** | `tunnel`, `covered`, `corridor`, `layer/level<0`, `arcade` 등 지하·실내 구간의 비용을 깎아 **지하상가를 최대한 경유**하는 경로를 따로 제시 |
| 🌡 **"언제 나가면 시원할까"** | 30분 간격 12시간치를 전부 다시 계산한 **출발 시각별 그늘 비율 막대그래프**. 막대를 누르면 그 시각으로 이동하고, 최적 출발 시각을 추천 (해가 없어 100%인 밤은 추천에서 제외) |
| 🕒 **도착 시점 그늘 반영** | 경로의 각 구간을 **실제로 지나가는 시각**의 그림자(15분 슬라이스)로 평가 — 걷는 동안 해가 움직여도 OK |
| 🔍 **한국 장소 검색** | 지역 데이터에 들어 있는 상점·건물·역 이름을 **로컬에서 즉시** 검색. 네트워크를 쓰지 않아 오프라인에서도 되고, **이름 일치도 × 근접도 × 장소 종류**로 정렬해 역·공원·대학이 먼저 나옴 |
| 📍 **30개 지역** | 서울 3대 도심(CBD·YBD·GBD)·분당·주요 대학가 + 부산·대구·인천·광주·대전·울산 번화가와 대학가. 한 지역당 약 200KB |
| 🍃 **그늘 산책 코스 추천** | 시작점에서 8방향 순환 루프를 생성해 그늘 비율·경로 다양성·목표 시간 부합도로 점수화, 상위 3개 추천 |
| 📊 **경로 리포트** | 거리·시간·그늘 비율·구간 스트립(그늘/햇빛/지하), 최단 경로 대비 "+230m (약 3분) 더 걷고 그늘 +24%p" 식의 직관적 비교 |
| 🏢 **건물 정보** | 지도에서 건물 클릭 → 높이·층수·현재 그림자 길이 팝업 |
| 🌲 **가로수·숲 반영** | OSM `natural=tree`, `tree_row`, `wood`, `landuse=forest`도 그늘로 계산 |

## 🚀 실행 방법

### 1) 그냥 열기 (가장 간단)
`index.html`을 브라우저로 열면 끝. (원격 API가 모두 CORS를 허용해서 `file://`로도 동작합니다.
단, "현재 위치" 버튼은 HTTPS/localhost에서만 동작해요.)

### 2) 로컬 서버 (권장)
```bash
# 파이썬
python -m http.server 8080
# 또는 Node
npx serve .
```
→ http://localhost:8080 접속

### 3) GitHub Pages 배포
1. 이 폴더를 GitHub 저장소로 푸시 (**`data/` 폴더를 꼭 포함**하세요)
2. 저장소 **Settings → Pages → Branch: `main` / root** 선택
3. 잠시 후 `https://<아이디>.github.io/<저장소>/` 에서 접속 🎉

특정 지역으로 바로 열리는 링크도 만들 수 있습니다 — 공유할 때 유용해요:

```
https://<아이디>.github.io/<저장소>/?region=sel-gbd
```

### 4) SNS 공유 카드 (선택)

링크를 인스타·X·쓰레드에 올릴 때 뜨는 미리보기 이미지입니다.
[`tools/make-og.html`](tools/make-og.html)을 브라우저로 열고 저장 버튼을 누르면 `og.jpg`가 받아집니다.
그 파일을 **프로젝트 맨 위 폴더**에 넣고 커밋하면 끝입니다. (`index.html`에 태그는 이미 걸려 있어요)

## 🧠 동작 원리

```mermaid
flowchart LR
    P[tools/prebake.js<br>개발자가 가끔 실행] -->|Overpass| Q[data/*.json<br>압축해 저장·커밋]
    Q --> B[그림자 엔진<br>태양위치 × 건물높이<br>15분 슬라이스 캐시]
    Q --> C[보행 그래프<br>교차점 노드 + 구간 엣지]
    B --> D["A* 라우팅<br>비용 = 시간 × (1 + α×햇빛)"]
    C --> D
    D --> E[그늘 경로 / 산책 코스<br>구간별 그늘·햇빛·지하 표시]
```

1. **데이터** — 건물(`building` + `height`/`building:levels`), 보행 가능 도로, 나무, 장소 이름을
   지역별로 미리 받아 `data/`에 넣어 둡니다. 좌표는 encoded polyline으로 압축해
   한 지역이 gzip 200KB 정도입니다. 앱은 이 정적 파일만 읽습니다.
2. **그림자** — 태양 고도 θ, 방위각을 [SunCalc](https://github.com/mourner/suncalc)로 구하고,
   건물 외곽선의 각 변을 태양 반대 방향으로 `높이 / tanθ` 만큼 밀어낸 폴리곤들의 합집합을
   그림자 영역으로 사용합니다. 시간을 15분 단위로 잘라 캐싱합니다.
3. **라우팅** — OSM 보행로로 그래프를 만들고, 구간을 12m 간격으로 샘플링해 햇빛 노출 비율을 구한 뒤
   `걷는시간 × 도로등급 × (1 + α × 노출비율)`을 비용으로 A* 탐색합니다.
   지하·실내 구간은 `÷ (1 + 지하선호도)`로 비용을 깎습니다(휴리스틱도 같은 비율로 낮춰 최적성 유지).
   `α`와 지하선호도 조합을 바꿔 **최단 / 그늘 / 지하도 세 경로를 각각** 풀어냅니다.
   구간별 그림자는 **출발 시각 + 그 구간까지 걸어온 시간**의 슬라이스로 평가하므로
   도착 시점의 그늘 변화까지 자연스럽게 반영됩니다.
4. **산책 코스** — 시작점 기준 8방향으로 다이아몬드형 경유점을 만들어 루프를 라우팅하고,
   그늘 비율(62%) + 경로 중복 회피(16%) + 목표 시간 부합도(22%)로 점수화해 상위 3개를 보여줍니다.
5. **검색** — 지역 데이터에 이름 있는 장소(상점·시설·역·건물)가 함께 들어 있어서,
   입력할 때마다 그 안에서 즉시 찾습니다. `이름 일치도 + 34·e^(-거리/2.2km) + 종류 가산점`으로
   정렬해 가깝고 쓸모 있는 것부터 보여줍니다. **외부 검색 서버를 부르지 않습니다.**

## 🗂 파일 구조

```
shadewalk/
├── index.html        # 마크업 + CDN 로드 (빌드 불필요)
├── css/style.css
├── data/             # ⚠️ 미리 구운 지역 데이터 — 반드시 커밋해야 앱이 동작
│   ├── index.json    #    지역 목록 (앱이 처음 읽는 파일)
│   └── sel-gbd.json  #    지역별 건물·보행로·장소
├── tools/
│   ├── regions.js    # 구울 지역 목록 (여기에 추가하면 됨)
│   └── prebake.js    # Overpass → data/ 굽기 (개발자가 가끔 실행)
└── js/
    ├── util.js       # 투영·격자 인덱스·폴리라인 도우미
    ├── codec.js      # 좌표 압축 (encoded polyline) — 굽는 쪽과 공용
    ├── sun.js        # SunCalc 래퍼 (그림자 방향/길이 계수)
    ├── osm.js        # OSM 태그 해석 규칙 (건물 높이 등)
    ├── regions.js    # 구운 지역 데이터 로더·디코더
    ├── shadow.js     # 그림자 폴리곤 생성 + 지점 그늘 판정 (15분 캐시)
    ├── graph.js      # 보행 그래프 + 시간 인지 그늘 가중 A*
    ├── course.js     # 순환 산책 코스 생성·점수화
    ├── geocode.js    # 지역 데이터 안에서 장소 검색 (오프라인)
    └── main.js       # 지도(MapLibre)·오버레이·UI 배선
```

## 🔄 지역 추가·갱신하기

`tools/regions.js`에 한 줄 추가하고 (`c` = 중심 좌표, `r` = 반경 m):

```js
{ id: 'bsn-gwangan', city: '부산', name: '광안리', sub: '광안리해변', c: [129.1180, 35.1530], r: 1400 },
```

굽습니다:

```bash
node tools/prebake.js bsn-gwangan
```

- 인자 없이 실행하면 **아직 없는 지역만** 굽습니다 (중간에 실패한 지역만 이어서 받을 때 편합니다)
- `--force` — 이미 있어도 **OSM에서 새로 받아** 다시 굽습니다 (지도 데이터가 갱신됐을 때)
- `--cached` — 받아 둔 원본(`.cache/`)으로만 다시 굽습니다. 압축 설정이나 필터를 바꿨을 때
  네트워크를 전혀 쓰지 않고 몇 초 만에 끝납니다

> 이 스크립트는 **개발자가 가끔 손으로 돌리는 용도**입니다. 공용 Overpass 서버를 배려해
> 한 번에 한 지역씩, 요청 사이에 6초씩 쉬며 받습니다. 병렬로 돌리지 마세요.
> 서버가 바쁘면 504가 자주 나는데, 정상입니다 — 시간을 두고 다시 돌리면 이어서 굽습니다.

## ⚠️ 한계 (알고 쓰면 더 좋아요)

- **커버 지역 밖에서는 동작하지 않습니다.** 미리 구운 30곳 안에서만 경로·검색이 됩니다.
  다른 동네가 필요하면 `tools/regions.js`에 추가하고 다시 구우면 됩니다 (위 참고).
- **지역 경계 근처는 그늘이 실제보다 적게 나옵니다.** 경계 바깥 건물의 그림자는 데이터에 없기 때문입니다.
  지역 가장자리 300m쯤은 참고만 하세요.
- **OSM 높이 데이터**: 강남 기준으로도 건물의 **76%는 높이 정보가 없어** 기본값(설정에서 6~24m)으로
  추정합니다. 실측값이 있으면 그 값을, 층수만 있으면 `층수 × 3.2 + 1.2m`로 계산합니다.
  ⚙️에서 동네 특성에 맞게 바꿔 보세요 — 그림자 길이가 눈에 띄게 달라집니다.
- **멀티폴리곤 건물 미지원**: 안뜰이 있는 대형 건물(relation)은 단순화되어 빠질 수 있습니다.
- **나무 그늘은 근사치**: 수관 크기 정보가 없어 반경 ~5m 원으로 근사합니다. 여름(잎이 무성한 상태) 기준입니다.
- **좌표 정밀도 약 1.1m**: 용량을 줄이려고 양자화했습니다. 그림자 계산에는 충분합니다.
- **도보 전용**: 직선거리 약 4km 이내 경로에 최적화되어 있습니다.
- **지형 미반영**: 산·언덕이 만드는 그림자, 고가도로의 높이차는 계산하지 않습니다.
- **지도 타일이 막혀도 동작**: 타일 서버가 응답하지 않으면 8초 뒤 배경 지도 없이 계산 기능만으로 시작합니다.
- **지도 타일은 CARTO 무료 티어**를 씁니다. 상업적으로 크게 쓸 계획이라면
  [CARTO 이용약관](https://carto.com/attributions)을 확인하거나 다른 타일 제공자로 바꾸세요.
